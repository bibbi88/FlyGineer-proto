# FlyGineer-proto – working notes for Claude

Tablet-first (Samsung Galaxy Tab A9, 8.7", 1340 × 800, landscape) paragliding flight instrument that runs in the browser, a self-made XCTrack-like app for the owner's **Bora_vario** Bluetooth variometer (https://github.com/bibbi88/Bora_vario). No build step, no framework: plain HTML/CSS/JS, deployed as static files (GitHub Pages, https required for Bluetooth and GPS). Tested on an Android tablet in Chrome.

## Branch rules
- Work on **`dev`**. Commit and push there.
- **Never merge to `main` until the owner explicitly asks.**

## Layout
- `index.html` – markup only, loads the files below in order.
- `css/style.css` – all styles.
- `data/demo-flight.js` – built-in demo flight (real XCTrack flight, delta-encoded). Start with `?demo` or from Settings.
- `js/` – classic scripts, loaded **in this order**, sharing one global scope (top-level `const`/`let`/functions are visible across files). Each file starts with `'use strict'`. Don't reorder; a file may only run top-level code that uses things from earlier files. Functions called later (from events or the main loop) can live anywhere.
  1. `01-core.js` helpers, settings `S` (saved), state `st`, data input
  2. `02-analysis.js` circling/wind/thermal/turn analysis, elevation and glide prediction, Bora over Bluetooth (Nordic UART, `$LK8EX1`), GPS
  3. `03-replay.js` demo simulator, IGC parse/replay (`parseIGC`, `finishIGC`, `demoIGC`, virtual clock `nowT()`), vario sound
  4. `04-map.js` Leaflet map widgets (`mapMount`, `mapDraw`, rotation smoothing, ADS-B traffic overlay)
  5. `05-data-sources.js` airspace, places (Overpass), task/FlyXC, NOTAM, forecast (Open-Meteo)
  6. `06-ui.js` page rendering, events
  7. `07-widgets.js` widget engine: grid, `WT` type table, `COMMON` options, `BTN` button actions, layouts per page, edit sheet (`openSheet`), pointer handling
  8. `08-actions.js` tap actions, detail popups, FlyXC "use this route", Start point, update rate and thermal mode, export/import, automatic actions
  9. `09-main.js` main loop, `boot()`
  10. `10-offline.js` service worker registration, "new version" banner, storage persistence, Settings → App & offline maps
  11. `11-planner.js` XC planner, its own main page `pPlan` (tab "Planner", page menu, button/tap action `pPlan`; the Next turnpoint widget's "Plan a route" opens it; map kept alive, `plMount` on show): `PL` state, `plMount`/`plDraw`/`plSide`, `plAnalyse` (open / out & return / flat / FAI triangle: 3 corners closed within 20 %), FAI sectors for the 3rd corner with 2–3 points, and with a triangle one area per corner (where it can move, the other two fixed, and stay FAI; blue, selected corner solid, others dashed; route line green when FAI, else dark), draft in localStorage `bora.plan`, "Use as my task" sets `st.task`; **saved routes** (`plRoutes`/`plRoutesSave`, localStorage `bora.routes`, newest first, max 60, same name = overwrite; side panel "💾 Saved routes" toggle with name field (auto name `plAutoName`), load = into the planner, ✕ with Undo; settings export carries `routes`, import adds by id). FlyXC-compatible: routes in/out as FlyXC `p=` links (paste field `#plFxIn`), and `plScore` = XContest scoring the way FlyXC's optimiser does it over the route points (free distance via ≤ 3 TPs ×1.0, flat ×1.2 / FAI ×1.4 triangles = perimeter − closing gap, gap ≤ 20 %). Map style switch Topo / Satellite / Airspace on the map (`plSetLayer`). Your position: `st.gpsPos` (the real device GPS, stored by the GPS watch even during a demo/replay) as a blue dot with accuracy ring (`plMe`), the replay/demo glider separately; ⌖ button (`plLocate`) centres on you and asks for a position if none yet.
- `sw.js` – service worker: app files cached per `VERSION`, Leaflet/fonts cached, map tiles cached as viewed (cache first, max `MAX_TILES`, oldest out first; fetched with CORS so the quota counts real sizes). Weather, airspace, traffic etc. are never cached.
- The replay bar (`#replayBar`) is shared by all widget pages and floats (hidden on Settings/Web via `body[data-page]`): −1 min / +1 min buttons `#rpBack`/`#rpFwd` (03 `replaySkip`: forward plays the minute through at once keeping all history; back = `seekReplay(frac, true)`, which rebuilds the whole flight from the start instead of only the last 2 min like the slider; under 1 s near the end of the demo at 6× CPU slowdown); drag by the grip `#rpGrip` (position `S.rpPos` as fractions of the screen), fold with `#rpMin` (`S.rpMin`); `placeReplayBar()` keeps it on screen. Widgets use the full height during a replay. Widget layers fill the whole page on every widget page (the top-right corner buttons float over them, as on the map).
- `preview.html` – desk preview: the app in an iframe inside an 8" tablet frame (default: the owner's tablet 1340×800, Galaxy Tab A9 8.7"; also Tab A 8.0 presets, custom size, portrait, fit / 100 % / real size). Not part of the app; the service worker only serves the stored app page for `/` and `index.html`, other pages come from the network.
- `manifest.webmanifest`, `icons/` – installable app (full screen, landscape).

## Releasing a change (PWA)
- **Bump `VERSION` in `sw.js` with every change to app files** (format `YYYY.MM.DD-n`), or installed apps keep the old copy. The tablet then shows "A new version is ready · Reload"; it never reloads by itself.
- New app files must be added to `SHELL` in `sw.js`, or they won't work offline (install fails if a listed file is missing).
- Hosting: GitHub Pages serves the `dev` branch at https://bibbi88.github.io/FlyGineer-proto/.

## Key concepts
- **Widgets**: every element on a page is a widget `{id,type,x,y,w,h,cfg,cfgT?}` on a grid (`GSC=4`, `GC=96`, `GR=64`). Per-page layouts in `S.layouts = {map,thermal,atmos,air}`; `S.layout` is a getter/setter for the current page. Text widgets are produced by `wData(W)`; canvas widgets by the `DRAW` table. `cfgT` holds settings used only while thermalling (`effCfg`/`cfgW`).
- **Adding a widget**: add a `WT` entry (name, description, default size, options), render it in `wData` or `DRAW`, add it to `GROUP` (detail popup) and to `DEFS` if it belongs in a default layout. `DEFS` = the owner's own exported setup (bora-settings-20261018.json, generated: cfg keys equal to the base `size auto / bg 70 / title shown` are left out, also `pad` 'page'/2, empty `label`/`units`, and hand-typed titles equal to the automatic "Vario 4s") in fine grid units; on a fresh install (`FRESH`, no stored settings) the one-time layout migrations are marked done so they don't alter it `[type, x, y, w, h, cfg]`; settings defaults `DEF` in 01-core from the same export (2026-10-18: layer sat, rate 1 / rateT 0.5, toTime 3, towWin 20, towRelT 8, thermBack pMap, fai off, auto rule tow start → sound off; callsign and radio message left generic; avgS 5 — no longer a setting: the Vario average widget's own `cfg.win`, default 30 s, migration `avgMig` copied the old value into widgets without one — layer topo, thermPage pThermal, sound on at 30 %, FAI sectors on).
- **Own pages** (`S.pages` = [{id: 'pU…', name}], max 20; 07 `pageMount`/`pageUnmount`/`pagesOrder`, `isUserPage`, `pageTitle`; 08 `pageAdd(name, fromLayoutKey)`/`pageRename`/`pageMove`/`pageDelete` (toast Undo)/`pagesSet`, `pagesLists()` rebuilds in place TAPG/HOLDG "Go to page", TAP/HOLD, `BTN` + the button action options, `PG_ALL`, `RULE_ACTS`): widget pages whose layout key is the page id (`PAGEKEY`/`LAYERID` extended at load), section `.page.custom` + tab inserted before Planner, empty-page hint `.emptyHint`; start empty or as a copy of any page; Settings → Pages & widgets. Body class `wpage` marks widget pages (replay bar). Export carries `pages`; import adds them (same id renamed). "Reset the built-in page layouts" leaves own pages alone.
- **Button widget**: actions come from `BTN`, run by `runAction`. `pSwitch` toggles Map/Thermal (hold = page menu with all pages); `fullscreen` toggles full screen. Full screen is also in the hamburger menu (last item, `#fullBtn`, label follows `fullscreenchange`); the Map page's Full screen button widget was removed from `DEFS` and once from stored layouts (`fullBtnMig`). Action `mute` (button "🔊 VARIO" / red "🔇 MUTED", toggles `S.sound`; Add widget → Buttons → Mute vario button) sits where that button was (DEFS and migration `muteBtnMig`, only if the spot is free).
- **Thermal assistant** (`ta`, `taDraw`) and layer view orientation: `cfg.orient` 'wind' (wind up = wind comes from the top), 'winddown' (wind comes from the bottom), 'north', 'track'.
- **Thermal assistant** positions: `cfg.frame` 'air' (default, the moving air: after leaving a thermal and drifting you stay near it) or 'ground' (like the side view); the map behind also uses ground. Title shows "in the air" / "over ground"; `coreEstimate(ground)` follows the same frame (the Centering widget stays in the air).
- **Thermal assistant** ideal path (`cfg.ideal`, default on; 06 `idealCircle`, `idealR`): while circling or in thermal mode, your next full turn as a dashed green loop starting where you are around the centre, in your turn direction (`st.turnRate` > 0 = right = clockwise), with the core's drift in the view over one turn period (`st.lastTurn.T`), so it stretches into an oval-like loop. Centre = `coreEstimate` (now also returns `age`, the weighted mean age of its samples) smoothed ~4 s (`I.Rx/Ry`), drift = its velocity smoothed ~20 s (capped at wind + 1.5 m/s; starts at 0.8 × wind over the ground, 0 in the air), shown centre moved on by drift × age. Radius: `idealR` fits climb vs radius over this thermal's turns (`st.turnLog`, one entry per turn from 02 `analyse`, max 12) and moves the last radius toward the better side by up to 15 % (label "ideal · r 38 m (tighter climbs better)"), smoothed ~10 s.
- **Thermal assistant** next turnpoint: magenta arrow on the rim pointing to it with name and distance (`cfg.tp`, default on, hidden after goal).
- **Thermal assistant** (`ta`, `taDraw`): track drawn as a trail by default (`cfg.style` 'trail' = trail + heat glow, 'trailonly', 'both' = dots + heat, 'dots', 'heat'); band coloured by climb with a thin outline, stronger on the last circle; `cfg.taper` 'on' (default, 2026-10-17): older pieces thinner (down to ~28 %) and paler (opaque colour faded toward `--card`, `fadeTo`), each piece with its own edge drawn in time order so newer passes lie on top; 'off' = the old same-width band.
- **Barometer** (02 `parseLine`/`baroFilter`/`baroAlt`, 06 `baroSection`/`baroLiveHTML`/`baroChart`/`baroWire`, 2026-10-18): the Bora firmware (bibbi88/Bora_vario, `generateLK8String`) sends `$LK8EX1,<pressure Pa, 1 decimal>,99999,9999,<temp>,<1000+battery %>,*<hex>\r\n` ~12/s plus `$XCTOD` lines, i.e. **only the pressure** (altitude/vario "not available"); the app used to read vario 9999 as 0. Now altitude = standard atmosphere from pressure and `S.qnh` (default 1013.25), vario = 2-state Kalman (height, climb) on it, response `S.baroTau` s (1; process noise q = 4R/τ⁴) and `S.baroNoise` m (0.3 = R); a device's own altitude/vario fields are used when present. BLE lines split on \r\n / \n / \r across packets. Settings → Vario & GPS → Barometer: live boxes, 30 s chart (raw dots, filtered altitude, vario), last 12 raw lines (`st.baroLines`), QNH stepper + set from GPS altitude / a known altitude / standard, filter steppers, "Use the measured noise" (σ raw − filtered over 10 s), CSV of the last 90 s (`st.baroLog`). Widget `baro` = Pressure (hPa, QNH).
- **Wind** (02 `windFit`/`windUpdate`, 2026-10-18): per full circle a least-squares circle fit of the ground-speed vectors (centre = wind, radius = airspeed); rejected when the airspeed scatters > 18 % or is implausible; at most one estimate per half turn (`st.windEst`, 10 min); `st.wind` = recency-weighted average (half weight after `S.windAvg` s, default 120, Flight modes → Circling) without estimates far off the rest (> max(1.5 m/s, 40 %)). Demo flight: total direction change 1732° → 166°. Used to mix each 1 s sample's circle mean in at 40 %.
- **Air positions**: every sample gets `ax, ay` (m, position in the moving air) when it is logged, built step by step with the wind known then (`analyse`); `airRel()` gives positions relative to you. Never re-apply the current wind to old points (that made the thermal views reshape with every wind update). The side/front views' axis is per widget (`sideAxis(view, cfg, cv)`, state `cv._ax`/`cv._axT`, never reuse those names in sideDraw: the redraw key is `cv._axShown`; `st.sideAx` = the last one, for reference): it turns when the wind direction has changed more than `cfg.axTurn`° (0–90 in 1° steps, 0 = always follow; default 10, 2026-10-18; was a fixed 30°), also during a thermal unless `cfg.axTherm` is off (was never during a thermal), and swings over smoothly (~1.5 s); the history is re-projected from stored positions, so nothing is lost.
- **Thermal side/front views** (`tside`, `tcross`, both drawn by `sideDraw`): recent track relative to you **over the ground** (owner's choice: positions only, no wind correction; option `cfg.frame` 'air'), axis = downwind (side) or 90° right of it (front), see Air positions for when it turns. Lift columns from circle-averaged centres (`liftCentres`) for the current and recent thermals.
- **Thermal heading view** (`thead`, also `sideDraw`, view 'head'): looks along your current heading (lightly smoothed, `cv._hd`; option `cfg.hold` keeps it while circling, off by default: the owner steers back to thermals with it), left ↔ right vs height, only points between just behind you and `cfg.ahead` (default 1000 m) ahead, fading with distance; remembered thermals labelled with their distance ahead. Side/front/heading views have on-widget ↔+ / ↔− buttons for the horizontal scale (`cfg.range`, actions `xin`/`xout`) and an "In air" / "Over gnd" button (action `sframe`, toggles `cfg.frame`, pressed = in the moving air).
- Side/front/heading views: your height in the view `cfg.ypos` % from the bottom (5–95, default 55; fixed scale).
- Side/front/heading views: without wind the axis is north → south (as if wind from the north); a small indicator top right (seen from above, up = looking direction) shows the wind direction in blue with its speed, or north in red while no wind is known. Edge labels are bearings only.
- Side/front views also keep finished thermals (`st.thermals[].cLL`, from `rememberThermal`) for `cfg.keep` min (default 5): centres over the ground (`cG`, or `cLL` in the moving air), anchored where you left it, with a dashed extension `cfg.ext` (default 200 m) above its top; off-screen ones get an edge marker.
- **Thermal 3D** (`t3d`, `t3dDraw`): hand-made perspective projection on a 2D canvas (no 3D library): faint height layers, track ribbon, one disc per circle centre, dashed rings above. Camera `cfg.cam` auto/behind/downwind/north (auto = behind while gliding, downwind while circling), turned smoothly (`el._yaw`); buttons ⟲ ⟳ (`cfg.yaw`), + − (`cfg.zoom`), Reset.
- **Thermal layer view** (`tlayer`, `layerDraw`): top view of all logged points from your height down `cfg.depth` (default 100 m), in the moving air (or `cfg.frame` 'ground'); marker = strongest group of lift in that slice, recent lift weighted higher. Only in Add widget (owner places it).
- **Thermal heat map** (`theat`, `heatMapDraw`): no track; samples (≥ 0.9 s apart, last `cfg.hist` s) splatted as Gaussians (`cfg.blur` m) onto a coarse screen grid, weighted by height closeness (`cfg.depth`) and recency (half weight at half the history), in the moving air (or `cfg.frame` 'ground'); cached per new sample in `el._hm`, drawn via a small offscreen canvas scaled up; low-data cells fade; core = strongest confident cell. `cfg.colors` 'rel' (default, colour scale spread over the lift found) or 'fixed'. Only in Add widget.
- **Compass wind arrow**: `cfg.windm` 'large' (default; old `true` = large) / 'across' / 'small' / false, `cfg.windc` colour, `cfg.winds` speed label., `cfg.windsz` speed size % (default 150), `cfg.windu` unit hide / show (app unit) / both (km/h + m/s); the label is kept inside the widget.
- Thermal widgets (`ta`, `tside`, `tcross`, `t3d`) use a **fixed scale** by default (`cfg.scale` 'fixed'|'auto', distances in `cfg.range`, `cfg.vspan`); the owner does not want them to rescale by themselves.
- **Small widgets**: canvas widgets under ~180 px in width or height get class `compact` (simpler drawing; maps excluded). On-widget buttons (`.wctl`) get class `ctlOff` (hidden, a faint ⋯ top right except on maps) when `cfg.ctlShow` is 'auto' (default) and the widget is compact or narrower than `S.ctlSmall` px (default 320; or lower than ¾ of it; 0 = never; Settings → Display & sound → Widget spacing), or always with 'tap'; 'always' = old behaviour. The first tap on such a widget only shows them for 6 s (`el._ctlUntil`, in the layer's pointerup before `handleTap`), a button press extends it. The edit-sheet row shows only for canvas widgets. Draw functions simplify by size: compass detail levels (full / 30° ticks + N / ring + N + big heading), wind direction and turn radius write the main value on the circle, labels and legends drop out below ~200 px. Check new canvas widgets at 2×2 and 3×3 grid cells.
- **Flight modes** (Settings → Flight modes, section key `modes`; 06 `modesSection`, live card `modeLiveHTML` refreshed every second, `MODE_KEYS` + Reset with Undo): all detection criteria as steppers, read with `sN(key, default)` (01; 0 is a valid value): takeoff `toSpd` km/h (14.4) for `toTime` s (0; `st.toSince`); circling `cirRate` °/s (7) over `cirWin` s (8) above `cirSpd` km/h (7.2), `st.turnRate`; thermal counted after `thRec` s (30); circling again within `thJoin` s (30) continues the same `st.thermal` (02 `analyse`: `end` removed, its `st.thermals` record `T.rec` updated, not duplicated); Thermal gain / Thermal avg widgets use `thRes()` in 07: live while circling, frozen at `alt1` once left, then the last recorded thermal (sub "last thermal"); thermal mode `modeAuto`, `modeEnter`, optional `modeClimbOn`/`modeClimb` (average climb since circling started), `modeHold`, page switch; tow `towDetect`, `towMin`, `towWin` s (90), release below `towRelV` m/s (0.3) for `towRelT` s (4); XC auto mode `xcOut` km (2), `xcBack` % (75), `xcTri` % (15); display update `rate`/`rateT`.
- **Thermal mode**: `updateMode/enterThermal/leaveThermal`, `st.thermMode`; page switching in 08 `setMode`: entering shows `S.thermPage` from any widget page (`st.preTh` = the page you were on, or `st.lastWPage` (set in `showPage`) if you were already on the thermal page); leaving goes back whenever the thermal page is still shown, even after manual page changes (2026-10-18; it used to need `st.autoSwitched`, which any manual page change cleared), to `S.thermBack`: true = page before (`st.preTh`), a page id, or false = stay; "automatic actions" (`AUTO_EVENTS`, `fireEvent`, `S.autoRules`) run actions on events with optional delay.
- **Vario widget** modes `cfg.mode` 'number' (text) / 'bar' / 'dial' (canvas via `varioDraw`; `isCv(W)` decides canvas vs text per widget, the element is rebuilt when it changes). Averaging `cfg.win` in 0.1 s steps (default title "Vario 1s" when set (`durS`, compact), plain "Vario" at 0; the Vario average widget's title is "Vario 30s" / "Vario 2min" from its `cfg.win`; an own title replaces it); tap option 'vmode' cycles the modes. Bar direction `cfg.barDir` 'auto' (by shape) / 'v' / 'h'.
- **Widget spacing** (Settings → Display & sound → Widget spacing; 06 `wStyle`/`wPad`): `S.wGap` px between widgets (default 4; map widgets always edge to edge), `wPadX`/`wPadY` inner padding (2/1 = tight, default since 2026-10-18; migration `padMig` moved stored 8/4 to 2/1 once), `wLab` title and sub-line size (12), `wRad` corner rounding (10), as CSS vars `--wpx --wpy --wlab --wrad` on `:root`; text values are fitted to the space that is left. Buttons Default (tight: 4, 2, 1, 12, 10) / Roomy (4, 8, 4, 12, 10) / Compact (1, 3, 1, 10, 4). Per widget `cfg.pad` ('page' = global, or px; vertical = half) in `COMMON`.
- **Edit sheet layout** (07 `sheetGroups`/`optRows`, `SHEET_SEC`): the widget's own options first; options matching a `SHEET_SEC` rule go into folding sections (`details.wsSec`: Track and glider, Task, Line back to start, Airspace, Places, Air traffic, Wind arrow at you, Buttons and position, When shown, Tap and hold, Look; closed by default, open ones remembered in `st.sheetOpen` while the app runs); two or more on/off options in a row (`isBoolOpt`) become one "On / off" row of toggle chips (✓ = on, `data-ok` with the opposite value). Map sheet went from ~6900 to ~2200 px. New options: put them in a section with a `SHEET_SEC` rule if they belong to one.
- **Widget titles**: per widget `cfg.showLabel` (edit sheet: Show/Hide beside the title text; size as Width/Height steppers in grid cells, 0.5 steps); global `S.titles` 'each' | 'hide' (Settings → Display, button action `titles`); titles always show in edit mode.
- **Task on the map** (`drawTaskInto(g, C)`, `taskStyle(C, live)`): route with halo, `cfg.taskCol` (default yellow; `TASK_COL` yellow/orange/magenta/green/blue/black/white), `cfg.taskStyle` solid/dashed/dotted, `cfg.taskW` px (default 5); legs already flown faint and dashed, next turnpoint cylinder in the task colour; live line from you to the next turnpoint (`I.toWp`, `cfg.towp` on/off, `cfg.towpCol` 'same' = task colour, `cfg.towpStyle` default dashed, `cfg.towpW` default 4). The route itself is static (turnpoint to turnpoint).
- **Skip / resume turnpoints** (05: `goWp(i)`, `taskResume()`): the task popup (tap the Next turnpoint widget) has ⏭ Skip / ⏮ Back one and a "Go to" per turnpoint (skipped ones marked in `st.wpSkip`); button/action `skipWp`. Whenever a task is set (FlyXC import, planner "Use as my task", storage sync) `taskResume` replays the flight log through its turnpoints in order, so ones already flown through count as reached.
- **Open in planner**: the task popup (and Settings → Task) has a `data-plopen` button → `plOpenTask()` in 11 (current task into the planner, previous draft kept in its undo history, then the Planner page). Removing a task: "Remove task" in the task popup (`data-taskdel`) and "Remove my task (name)" in the planner (`#plDelTask`, shown whenever a task is set; clearing the planner alone does not touch the task), both with Undo.
- **Replay Start**: `replayLaunch(pts)` in 03 = first point moving > 4 m/s over 5 s; stored as `st.replay.launch` and put back into `st.takeoffPos` after every `seekReplay` (seeking used to move the Start to where you jumped); Set Start here during a replay updates it.
- **Next turnpoint** widget shows Dist, Req L/D (to the turnpoint, with `S.safety` above ground; red when above `S.wingLD`; replaced Brg 2026-10-17) and ETA.
- **Next turnpoint** reached: `st.wpHit` → widget green for 20 s, title "✓ TP1 reached · next TP2"; last point = goal (`st.goalT`, widget green "✓ GOAL"). Both reset on task import/clear. Text widgets may return `bgc`/`col` (class `tint`); `wData(W, box)` gets the widget size.
- **Next turnpoint** without a task: link field `.fxIn` (pasting a FlyXC link with a route imports it; Import button `fximp` uses the field or the clipboard) and "Plan in FlyXC" (`fxweb` opens the Web page on FlyXC). Pointer handling ignores taps on inputs inside widgets (no tap action, no long-press edit).
- **FlyXC link** (`flyxcUrl`, `taskLink`, `encodePolyline` in 05): the Web page opens FlyXC with `?p=` = the current task, or a 6 km east–west starter line at your position (cached per 0.01°, so the frame does not reload as you move): FlyXC starts its planner whenever `p` is set. FlyXC has no link parameter for airspaces and does not remember that toggle (always off at start; cross-origin frame, so the app cannot switch it). Button/action `copyTask` copies the task as a FlyXC link.
- **FAI triangle assistant** (`S.fai`, button/tap action `fai`; `faiState`/`faiSectors`/`faiCalc`/`faiDrawInto` in 05): start = Start point, 1st turnpoint = farthest point from it (scanned by log time); maps draw the two sectors where the 3rd point gives every leg ≥ 28 % (`FAI_MIN`) plus the line back to start (04 `homeLine`, map options `home` fai (default: with the sectors) / always / off, `homeLeg` tri = TP → you → start / start = you → start, `homeCol` (`TASK_COL`, green), `homeStyle` dashed, `homeW` 3 px, `homeLab` "⌂ 7.5 km" label at the middle); widget `fai` = **XC flight** (2026-10-16, `xcCalc(mode)` in 05 uses `faiCalc(true)` so it works with the map sectors off): `cfg.mode` auto / line (from start, farthest, away speed over 60 s, heading from start) / oar (turnpoint = farthest, back to start, 2× total, done %) / tri (perimeter, shortest leg %, to FAI sector, back to start; green when FAI); auto = line while > 75 % of the farthest distance out or under 2 km, then triangle if the shortest leg ≥ 15 %, else out & return; `cfg.away`, `cfg.avg` (XC average = farthest / flight time); default tap and hold 'details' = `openXcInfo`/`xcInfoHTML` in 08 (all three modes as stat boxes, the mode `auto` picks highlighted; tap popup adds the FAI sectors switch and mode pills, delegated clicks on `#hBody`; hold shows it in `holdPop`); option `xcmode` still cycles modes (migrations `xcMig`, `xcMig2`). The orange FAI ON map button was removed from the defaults and once from stored Map layouts (`faiBtnMig`).
- **Climb history** (`climb`, `histDraw`): `cfg.time` s back (10–3600, default 120; vario history ≤ 300 s, else the 1 s flight log), fixed `cfg.scale` m/s up (default 5), sink down to 60 % of it.
- **Acoustic vario** (03 `beep`; Settings → Display & sound → Acoustic vario): `S.sound`, volume `S.volPct` (mirrors `S.volume`), climb tone from `vLift`, sink alarm `vSinkOn`/`vSink`, pitch `vF0` + `vFk` per m/s, beep speed `vRate`, tone `vWave` square/triangle/sine, near-lift ticks `vBuzz`, sound averaging `vDamp` s; test buttons (`beep.testRate`) play 3 s even with sound off.

## Testing (no framework yet)
Headless Chromium with Playwright works: `/opt/pw-browsers/chromium`, `playwright` installed globally in the cloud sandbox. The sandbox cannot reach CDNs, so route the Leaflet URLs to local copies (`npm pack leaflet@1.9.4 leaflet-rotate@0.2.8`) and stub or abort other external requests. Useful checks: open `index.html?demo`, no `pageerror`s; tap/hold buttons; open the edit sheet via `enterEdit(); openSheet(id)`; hit-test overlays with real pointer events. jsdom needs many stubs (canvas, layout, `L.Browser.any3d=true`), so prefer Chromium. Headless tests cannot judge how it looks or feels on the tablet; say so honestly.
Run `node --check js/*.js sw.js` after every edit. Responsiveness: measure taps with CPU throttling (`Emulation.setCPUThrottlingRate` 6, `deviceScaleFactor` 2) and the Event Timing API or a trace; headless draws canvases in software, so canvas timings overstate the tablet's GPU cost. To test the service worker, route with `context.route` (not `page.route`) and run with `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, otherwise the worker's own requests bypass the stubs; stubbed tiles need an `access-control-allow-origin: *` header.

## Product decisions and preferences (from the owner)
- Glove-friendly: large touch targets, no tiny controls. Landscape tablet is the main layout.
- Everything configurable, XCTrack-like: every page, every element a widget, duplicates allowed, small resize steps, blue drag handles on all corners.
- Numeric settings use − / number / + steppers (no preset pills). Option groups should be compact and grouped by function.
- Hamburger menu (top right) opens downward; page tabs auto-hide.
- Flights recorded here would be **unsigned IGC**: XContest accepts them but gives **no points**. The owner uses XCTrack on a separate phone for competition upload. There is no public XContest upload API.

## Known gaps / ideas
- IGC recording and saving from this app is not built yet (would need flight start/stop detection and periodic safety saves; downloading a file is fine).
- OGN (glider) traffic: no browser-friendly feed found; would need a small relay.
- Unverified: whether adsb.fi allows browser (CORS) requests from the hosted page; Flyk/FlyXC embedding permissions; ais.fi CORS; OpenAIP API details.
