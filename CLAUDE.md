# FlyGineer-proto – working notes for Claude

Tablet-first (Samsung Galaxy Tab A9, 8.7", 1340 × 800, landscape) paragliding flight instrument that runs in the browser, a self-made XCTrack-like app for the owner's **Bora_vario** Bluetooth variometer (https://github.com/bibbi88/Bora_vario). No build step, no framework: plain HTML/CSS/JS, deployed as static files (GitHub Pages, https required for Bluetooth and GPS). Tested on an Android tablet in Chrome.

## Branch rules
- Work on **`dev`**. Commit and push there.
- **Never merge to `main` until the owner explicitly asks.**

## Layout

- `css/style.css` – all styles.

## Releasing a change (PWA)
- **Bump `VERSION` in `sw.js` with every change to app files** (format `YYYY.MM.DD-n`), or installed apps keep the old copy. The tablet then shows "A new version is ready · Reload"; it never reloads by itself.
- New app files must be added to `SHELL` in `sw.js`, or they won't work offline (install fails if a listed file is missing).
- Hosting: GitHub Pages serves the `dev` branch at https://bibbi88.github.io/FlyGineer-proto/.

## Key concepts
- **Widgets**: every element on a page is a widget `{id,type,x,y,w,h,cfg,cfgT?}` on a grid (`GSC=4`, `GC=96`, `GR=64`). Per-page layouts in `S.layouts = {map,thermal,atmos,air}`; `S.layout` is a getter/setter for the current page. Text widgets are produced by `wData(W)`; canvas widgets by the `DRAW` table. `cfgT` holds settings used only while thermalling (`effCfg`/`cfgW`).
- **Adding a widget**: add a `WT` entry (name, description, default size, options), render it in `wData` or `DRAW`, add it to `GROUP` (detail popup) and to `DEFS` if it belongs in a default layout. `DEFS` = the owner's own exported setup (bora-settings-20261018.json, generated: cfg keys equal to the base `size auto / bg 70 / title shown` are left out, also `pad` 'page'/2, empty `label`/`units`, and hand-typed titles equal to the automatic "Vario 4s") in fine grid units; on a fresh install (`FRESH`, no stored settings) the one-time layout migrations are marked done so they don't alter it `[type, x, y, w, h, cfg]`; settings defaults `DEF` in 01-core from the same export (2026-10-18: layer sat, rate 1 / rateT 0.5, toTime 3, towWin 20, towRelT 8, thermBack pMap, fai off, auto rule tow start → sound off; callsign and radio message left generic; avgS 5 — no longer a setting: the Vario average widget's own `cfg.win`, default 30 s, migration `avgMig` copied the old value into widgets without one — layer topo, thermPage pThermal, sound on at 30 %, FAI sectors on).
- **Own pages** (`S.pages` = [{id: 'pU…', name}], max 20; 07 `pageMount`/`pageUnmount`/`pagesOrder`, `isUserPage`, `pageTitle`; 08 `pageAdd(name, fromLayoutKey)`/`pageRename`/`pageMove`/`pageDelete` (toast Undo)/`pagesSet`, `pagesLists()` rebuilds in place TAPG/HOLDG "Go to page", TAP/HOLD, `BTN` + the button action options, `PG_ALL`, `RULE_ACTS`): widget pages whose layout key is the page id (`PAGEKEY`/`LAYERID` extended at load), section `.page.custom` + tab inserted before Planner, empty-page hint `.emptyHint`; start empty or as a copy of any page; Settings → Pages & widgets. Body class `wpage` marks widget pages (replay bar). Export carries `pages`; import adds them (same id renamed). "Reset the built-in page layouts" leaves own pages alone.
- **Button widget**: actions come from `BTN`, run by `runAction`. `pSwitch` toggles Map/Thermal (hold = page menu with all pages); `fullscreen` toggles full screen. Full screen is also in the hamburger menu (last item, `#fullBtn`, label follows `fullscreenchange`); the Map page's Full screen button widget was removed from `DEFS` and once from stored layouts (`fullBtnMig`). Action `mute` (button "🔊 VARIO" / red "🔇 MUTED", toggles `S.sound`; Add widget → Buttons → Mute vario button) sits where that button was (DEFS and migration `muteBtnMig`, only if the spot is free).
- **Thermal assistant** (`ta`, `taDraw`) and layer view orientation: `cfg.orient` 'wind' (wind up = wind comes from the top), 'winddown' (wind comes from the bottom), 'north', 'track'.
- **Thermal assistant** positions: `cfg.frame` 'air' (default, the moving air: after leaving a thermal and drifting you stay near it) or 'ground' (like the side view); the map behind also uses ground. Title shows "in the air" / "over ground"; `coreEstimate(ground)` follows the same frame (the Centering widget stays in the air).
- **Thermal assistant** ideal path (`cfg.ideal`, default on; 06 `idealCircle`, `idealR`): while circling or in thermal mode, your next full turn as a dashed green loop starting where you are around the centre, in your turn direction (`st.turnRate` > 0 = right = clockwise), with the core's drift in the view over one turn period (`st.lastTurn.T`), so it stretches into an oval-like loop. Centre = `coreEstimate` (now also returns `age`, the weighted mean age of its samples) smoothed ~4 s (`I.Rx/Ry`), drift = its velocity smoothed ~20 s (capped at wind + 1.5 m/s; starts at 0.8 × wind over the ground, 0 in the air), shown centre moved on by drift × age. Radius: `idealR` fits climb vs radius over this thermal's turns (`st.turnLog`, one entry per turn from 02 `analyse`, max 12) and moves the last radius toward the better side by up to 15 % (label "ideal · r 38 m (tighter climbs better)"), smoothed ~10 s.
- **Thermal assistant** next turnpoint: magenta arrow on the rim pointing to it with name and distance (`cfg.tp`, default on, hidden after goal).
- **Thermal assistant** (`ta`, `taDraw`): track drawn as a trail by default (`cfg.style` 'trail' = trail + heat glow, 'trailonly', 'both' = dots + heat, 'dots', 'heat'); band coloured by climb with a thin outline, stronger on the last circle; `cfg.taper` 'on' (default, 2026-10-17): older pieces thinner (down to ~28 %) and paler (opaque colour faded toward `--card`, `fadeTo`), each piece with its own edge drawn in time order so newer passes lie on top; 'off' = the old same-width band.
- **Barometer** (02 `parseLine`/`baroFilter`/`baroAlt`, 06 `baroSection`/`baroLiveHTML`/`baroChart`/`baroWire`, 2026-10-18): the Bora firmware (bibbi88/Bora_vario, `generateLK8String`) sends `$LK8EX1,<pressure Pa, 1 decimal>,99999,9999,<temp>,<1000+battery %>,*<hex>\r\n` ~12/s plus `$XCTOD` lines, i.e. **only the pressure** (altitude/vario "not available"); the app used to read vario 9999 as 0. Now altitude = standard atmosphere from pressure and `S.qnh` (default 1013.25), vario = 2-state Kalman (height, climb) on it, response `S.baroTau` s (1; process noise q = 4R/τ⁴) and `S.baroNoise` m (0.3 = R); a device's own altitude/vario fields are used when present. BLE lines split on \r\n / \n / \r across packets. Settings → Vario & GPS → Barometer: live boxes, 30 s chart (raw dots, filtered altitude, vario), last 12 raw lines (`st.baroLines`), QNH stepper + set from GPS altitude / a known altitude / standard, filter steppers, "Use the measured noise" (σ raw − filtered over 10 s), CSV of the last 90 s (`st.baroLog`). Widget `baro` = Pressure (hPa, QNH).
- **Wind** (02 `windFit`/`windUpdate`, 2026-10-18): per full circle a least-squares circle fit of the ground-speed vectors (centre = wind, radius = airspeed); rejected when the airspeed scatters > 18 % or is implausible; at most one estimate per half turn (`st.windEst`, 10 min); `st.wind` = recency-weighted average (half weight after `S.windAvg` s, default 120, Flight modes → Circling) without estimates far off the rest (> max(1.5 m/s, 40 %)). Demo flight: total direction change 1732° → 166°. Used to mix each 1 s sample's circle mean in at 40 %.

## Testing (no framework yet)
Headless Chromium with Playwright works: `/opt/pw-browsers/chromium`, `playwright` installed globally in the cloud sandbox. The sandbox cannot reach CDNs, so route the Leaflet URLs to local copies (`npm pack leaflet@1.9.4 leaflet-rotate@0.2.8`) and stub or abort other external requests. Useful checks: open `index.html?demo`, no `pageerror`s; tap/hold buttons; open the edit sheet via `enterEdit(); openSheet(id)`; hit-test overlays with real pointer events. jsdom needs many stubs (canvas, layout, `L.Browser.any3d=true`), so prefer Chromium. Headless tests cannot judge how it looks or feels on the tablet; say so honestly.
Run `node --check js/*.js sw.js` after every edit. Responsiveness: measure taps with CPU throttling (`Emulation.setCPUThrottlingRate` 6, `deviceScaleFactor` 2) and the Event Timing API or a trace; headless draws canvases in software, so canvas timings overstate the tablet's GPU cost. To test the service worker, route with `context.route` (not `page.route`) and run with `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, otherwise the worker's own requests bypass the stubs; stubbed tiles need an `access-control-allow-origin: *` header.

## Product decisions and preferences (from the owner)
- Glove-friendly: large touch targets, no tiny controls. Landscape tablet is the main layout.
- Everything configurable, XCTrack-like: every page, every element a widget, duplicates allowed, small resize steps, blue drag handles on all corners.
- Numeric settings use − / number / + steppers (no preset pills). Option groups should be compact and grouped by function.
- Hamburger menu (top right) opens downward; page tabs auto-hide.
- Flights recorded here would be **unsigned IGC**: XContest accepts them but gives **no points**. The owner uses XCTrack on a separate phone for competition upload. There is no public XContest upload API.
