# FlyGineer-proto – working notes for Claude

Tablet-first (Samsung Galaxy Tab A9, 8.7", 1340 × 800, landscape) paragliding flight instrument that runs in the browser, a self-made XCTrack-like app for the owner's **Bora_vario** Bluetooth variometer (https://github.com/bibbi88/Bora_vario). No build step, no framework: plain HTML/CSS/JS, deployed as static files (GitHub Pages, https required for Bluetooth and GPS). Tested on an Android tablet in Chrome.

## Branch rules
- Work on **`dev`**. Commit and push there.
- **Never merge to `main` until the owner explicitly asks.**

## Layout
- `index.html` – markup only, loads the files below in order.
- `css/style.css` – all styles.
- `data/demo-flight.js` – built-in demo flight (real XCTrack flight, delta-encoded). Start with `?demo` or from Settings.
- `js/` – classic scripts, loaded **in this order**, sharing one global scope (top-level `const`/`let`/functions are visible across files). Each file starts with `'use strict'`. Don't reorder; a file may only run top-level code that uses things from earlier files. Functions called later (from events or the main loop) can live anywhere.
  1. `01-core.js` helpers, settings `S` (saved), state `st`, data input
  2. `02-analysis.js` circling/wind/thermal/turn analysis, elevation and glide prediction, Bora over Bluetooth (Nordic UART, `$LK8EX1`), GPS
  3. `03-replay.js` demo simulator, IGC parse/replay (`parseIGC`, `finishIGC`, `demoIGC`, virtual clock `nowT()`), vario sound
  4. `04-map.js` Leaflet map widgets (`mapMount`, `mapDraw`, rotation smoothing, ADS-B traffic overlay)
  5. `05-data-sources.js` airspace, places (Overpass), task/FlyXC, NOTAM, forecast (Open-Meteo)
  6. `06-ui.js` page rendering, events
  7. `07-widgets.js` widget engine: grid, `WT` type table, `COMMON` options, `BTN` button actions, layouts per page, edit sheet (`openSheet`), pointer handling
  8. `08-actions.js` tap actions, detail popups, FlyXC "use this route", Start point, update rate and thermal mode, export/import, automatic actions
  9. `09-main.js` main loop, `boot()`
  10. `10-offline.js` service worker registration, "new version" banner, storage persistence, Settings → App & offline maps
  11. `11-planner.js` XC planner, its own main page `pPlan` (tab "Planner", page menu, button/tap action `pPlan`; the Next turnpoint widget's "Plan a route" opens it; map kept alive, `plMount` on show): `PL` state, `plMount`/`plDraw`/`plSide`, `plAnalyse` (open / out & return / flat / FAI triangle: 3 corners closed within 20 %), FAI sectors for the 3rd corner with 2–3 points, and with a triangle one area per corner (where it can move, the other two fixed, and stay FAI; blue, selected corner solid, others dashed; route line green when FAI, else dark), draft in localStorage `bora.plan`, "Use as my task" sets `st.task`. FlyXC-compatible: routes in/out as FlyXC `p=` links (paste field `#plFxIn`), and `plScore` = XContest scoring the way FlyXC's optimiser does it over the route points (free distance via ≤ 3 TPs ×1.0, flat ×1.2 / FAI ×1.4 triangles = perimeter − closing gap, gap ≤ 20 %). Map style switch Topo / Satellite / Airspace on the map (`plSetLayer`). Your position: `st.gpsPos` (the real device GPS, stored by the GPS watch even during a demo/replay) as a blue dot with accuracy ring (`plMe`), the replay/demo glider separately; ⌖ button (`plLocate`) centres on you and asks for a position if none yet.
- `sw.js` – service worker: app files cached per `VERSION`, Leaflet/fonts cached, map tiles cached as viewed (cache first, max `MAX_TILES`, oldest out first; fetched with CORS so the quota counts real sizes). Weather, airspace, traffic etc. are never cached.
- The replay bar (`#replayBar`) is shared by all widget pages and floats (hidden on Settings/Web via `body[data-page]`): drag by the grip `#rpGrip` (position `S.rpPos` as fractions of the screen), fold with `#rpMin` (`S.rpMin`); `placeReplayBar()` keeps it on screen. Widgets use the full height during a replay. Widget layers fill the whole page on every widget page (the top-right corner buttons float over them, as on the map).
- `preview.html` – desk preview: the app in an iframe inside an 8" tablet frame (default: the owner's tablet 1340×800, Galaxy Tab A9 8.7"; also Tab A 8.0 presets, custom size, portrait, fit / 100 % / real size). Not part of the app; the service worker only serves the stored app page for `/` and `index.html`, other pages come from the network.
- `manifest.webmanifest`, `icons/` – installable app (full screen, landscape).

## Releasing a change (PWA)
- **Bump `VERSION` in `sw.js` with every change to app files** (format `YYYY.MM.DD-n`), or installed apps keep the old copy. The tablet then shows "A new version is ready · Reload"; it never reloads by itself.
- New app files must be added to `SHELL` in `sw.js`, or they won't work offline (install fails if a listed file is missing).
- Hosting: GitHub Pages serves the `dev` branch at https://bibbi88.github.io/FlyGineer-proto/.

## Key concepts
- **Widgets**: every element on a page is a widget `{id,type,x,y,w,h,cfg,cfgT?}` on a grid (`GSC=4`, `GC=96`, `GR=64`). Per-page layouts in `S.layouts = {map,thermal,atmos,air}`; `S.layout` is a getter/setter for the current page. Text widgets are produced by `wData(W)`; canvas widgets by the `DRAW` table. `cfgT` holds settings used only while thermalling (`effCfg`/`cfgW`).
- **Adding a widget**: add a `WT` entry (name, description, default size, options), render it in `wData` or `DRAW`, add it to `GROUP` (detail popup) and to `DEFS` if it belongs in a default layout. `DEFS` = the owner's own exported setup (2026-10-12, updated 11:10) in fine grid units; on a fresh install (`FRESH`, no stored settings) the one-time layout migrations are marked done so they don't alter it `[type, x, y, w, h, cfg]`; settings defaults `DEF` in 01-core (layer sat, rate 0.5 from that export).
- **Own pages** (`S.pages` = [{id: 'pU…', name}], max 20; 07 `pageMount`/`pageUnmount`/`pagesOrder`, `isUserPage`, `pageTitle`; 08 `pageAdd(name, fromLayoutKey)`/`pageRename`/`pageMove`/`pageDelete` (toast Undo)/`pagesSet`, `pagesLists()` rebuilds in place TAPG/HOLDG "Go to page", TAP/HOLD, `BTN` + the button action options, `PG_ALL`, `RULE_ACTS`): widget pages whose layout key is the page id (`PAGEKEY`/`LAYERID` extended at load), section `.page.custom` + tab inserted before Planner, empty-page hint `.emptyHint`; start empty or as a copy of any page; Settings → Pages & widgets. Body class `wpage` marks widget pages (replay bar). Export carries `pages`; import adds them (same id renamed). "Reset the built-in page layouts" leaves own pages alone.
- **Button widget**: actions come from `BTN`, run by `runAction`. `pSwitch` toggles Map/Thermal (hold = page menu with all pages); `fullscreen` toggles full screen.
- **Thermal assistant** (`ta`, `taDraw`) and layer view orientation: `cfg.orient` 'wind' (wind up = wind comes from the top), 'winddown' (wind comes from the bottom), 'north', 'track'.
- **Thermal assistant** positions: `cfg.frame` 'air' (default, the moving air: after leaving a thermal and drifting you stay near it) or 'ground' (like the side view); the map behind also uses ground. Title shows "in the air" / "over ground"; `coreEstimate(ground)` follows the same frame (the Centering widget stays in the air).
- **Thermal assistant** next turnpoint: magenta arrow on the rim pointing to it with name and distance (`cfg.tp`, default on, hidden after goal).
- **Thermal assistant** (`ta`, `taDraw`): track drawn as a trail by default (`cfg.style` 'trail' = trail + heat glow, 'trailonly', 'both' = dots + heat, 'dots', 'heat'); band coloured by climb with a thin outline, stronger on the last circle.
- **Air positions**: every sample gets `ax, ay` (m, position in the moving air) when it is logged, built step by step with the wind known then (`analyse`); `airRel()` gives positions relative to you. Never re-apply the current wind to old points (that made the thermal views reshape with every wind update). The side views' axis `st.sideAx` only turns when the wind changes > 30° and never during a thermal.
- **Thermal side/front views** (`tside`, `tcross`, both drawn by `sideDraw`): recent track relative to you **over the ground** (owner's choice: positions only, no wind correction; option `cfg.frame` 'air'), axis = downwind (side) or 90° right of it (front), fixed per thermal (`th.axis`). Lift columns from circle-averaged centres (`liftCentres`) for the current and recent thermals.
- **Thermal heading view** (`thead`, also `sideDraw`, view 'head'): looks along your current heading (lightly smoothed, `cv._hd`; option `cfg.hold` keeps it while circling, off by default: the owner steers back to thermals with it), left ↔ right vs height, only points between just behind you and `cfg.ahead` (default 1000 m) ahead, fading with distance; remembered thermals labelled with their distance ahead. Side/front/heading views have on-widget ↔+ / ↔− buttons for the horizontal scale (`cfg.range`, actions `xin`/`xout`).
- Side/front/heading views: your height in the view `cfg.ypos` % from the bottom (5–95, default 55; fixed scale).
- Side/front/heading views: without wind the axis is north → south (as if wind from the north); a small indicator top right (seen from above, up = looking direction) shows the wind direction in blue with its speed, or north in red while no wind is known. Edge labels are bearings only.
- Side/front views also keep finished thermals (`st.thermals[].cLL`, from `rememberThermal`) for `cfg.keep` min (default 5): centres over the ground (`cG`, or `cLL` in the moving air), anchored where you left it, with a dashed extension `cfg.ext` (default 200 m) above its top; off-screen ones get an edge marker.
- **Thermal 3D** (`t3d`, `t3dDraw`): hand-made perspective projection on a 2D canvas (no 3D library): faint height layers, track ribbon, one disc per circle centre, dashed rings above. Camera `cfg.cam` auto/behind/downwind/north (auto = behind while gliding, downwind while circling), turned smoothly (`el._yaw`); buttons ⟲ ⟳ (`cfg.yaw`), + − (`cfg.zoom`), Reset.
- **Thermal layer view** (`tlayer`, `layerDraw`): top view of all logged points from your height down `cfg.depth` (default 100 m), in the moving air (or `cfg.frame` 'ground'); marker = strongest group of lift in that slice, recent lift weighted higher. Only in Add widget (owner places it).
- **Thermal heat map** (`theat`, `heatMapDraw`): no track; samples (≥ 0.9 s apart, last `cfg.hist` s) splatted as Gaussians (`cfg.blur` m) onto a coarse screen grid, weighted by height closeness (`cfg.depth`) and recency (half weight at half the history), in the moving air (or `cfg.frame` 'ground'); cached per new sample in `el._hm`, drawn via a small offscreen canvas scaled up; low-data cells fade; core = strongest confident cell. `cfg.colors` 'rel' (default, colour scale spread over the lift found) or 'fixed'. Only in Add widget.
- **Compass wind arrow**: `cfg.windm` 'large' (default; old `true` = large) / 'across' / 'small' / false, `cfg.windc` colour, `cfg.winds` speed label.
- Thermal widgets (`ta`, `tside`, `tcross`, `t3d`) use a **fixed scale** by default (`cfg.scale` 'fixed'|'auto', distances in `cfg.range`, `cfg.vspan`); the owner does not want them to rescale by themselves.
- **Small widgets**: canvas widgets under ~180 px in width or height get class `compact` (on-widget buttons hidden; maps excluded). Draw functions simplify by size: compass detail levels (full / 30° ticks + N / ring + N + big heading), wind direction and turn radius write the main value on the circle, labels and legends drop out below ~200 px. Check new canvas widgets at 2×2 and 3×3 grid cells.
- **Thermal mode**: `updateMode/enterThermal/leaveThermal`, `st.thermMode`; "automatic actions" (`AUTO_EVENTS`, `fireEvent`, `S.autoRules`) run actions on events with optional delay.
- **Vario widget** modes `cfg.mode` 'number' (text) / 'bar' / 'dial' (canvas via `varioDraw`; `isCv(W)` decides canvas vs text per widget, the element is rebuilt when it changes). Averaging `cfg.win` in 0.1 s steps; tap option 'vmode' cycles the modes. Bar direction `cfg.barDir` 'auto' (by shape) / 'v' / 'h'.
- **Widget titles**: per widget `cfg.showLabel` (edit sheet: Show/Hide beside the title text; size as Width/Height steppers in grid cells, 0.5 steps); global `S.titles` 'each' | 'hide' (Settings → Display, button action `titles`); titles always show in edit mode.
- **Task on the map** (`drawTaskInto(g, C)`, `taskStyle(C, live)`): route with halo, `cfg.taskCol` (default yellow; `TASK_COL` yellow/orange/magenta/green/blue/black/white), `cfg.taskStyle` solid/dashed/dotted, `cfg.taskW` px (default 5); legs already flown faint and dashed, next turnpoint cylinder in the task colour; live line from you to the next turnpoint (`I.toWp`, `cfg.towp` on/off, `cfg.towpCol` 'same' = task colour, `cfg.towpStyle` default dashed, `cfg.towpW` default 4). The route itself is static (turnpoint to turnpoint).
- **Skip / resume turnpoints** (05: `goWp(i)`, `taskResume()`): the task popup (tap the Next turnpoint widget) has ⏭ Skip / ⏮ Back one and a "Go to" per turnpoint (skipped ones marked in `st.wpSkip`); button/action `skipWp`. Whenever a task is set (FlyXC import, planner "Use as my task", storage sync) `taskResume` replays the flight log through its turnpoints in order, so ones already flown through count as reached.
- **Next turnpoint** reached: `st.wpHit` → widget green for 20 s, title "✓ TP1 reached · next TP2"; last point = goal (`st.goalT`, widget green "✓ GOAL"). Both reset on task import/clear. Text widgets may return `bgc`/`col` (class `tint`); `wData(W, box)` gets the widget size.
- **Next turnpoint** without a task: link field `.fxIn` (pasting a FlyXC link with a route imports it; Import button `fximp` uses the field or the clipboard) and "Plan in FlyXC" (`fxweb` opens the Web page on FlyXC). Pointer handling ignores taps on inputs inside widgets (no tap action, no long-press edit).
- **FlyXC link** (`flyxcUrl`, `taskLink`, `encodePolyline` in 05): the Web page opens FlyXC with `?p=` = the current task, or a 6 km east–west starter line at your position (cached per 0.01°, so the frame does not reload as you move): FlyXC starts its planner whenever `p` is set. FlyXC has no link parameter for airspaces and does not remember that toggle (always off at start; cross-origin frame, so the app cannot switch it). Button/action `copyTask` copies the task as a FlyXC link.
- **FAI triangle assistant** (`S.fai`, button/tap action `fai`; `faiState`/`faiSectors`/`faiCalc`/`faiDrawInto` in 05): start = Start point, 1st turnpoint = farthest point from it (scanned by log time); maps draw the two sectors where the 3rd point gives every leg ≥ 28 % (`FAI_MIN`) plus dashed legs TP → you → start; widget `fai` = calculator (triangle, shortest leg %, distance to sector, back to start).
- **Climb history** (`climb`, `histDraw`): `cfg.time` s back (10–3600, default 120; vario history ≤ 300 s, else the 1 s flight log), fixed `cfg.scale` m/s up (default 5), sink down to 60 % of it.
- **Acoustic vario** (03 `beep`; Settings → Display & sound → Acoustic vario): `S.sound`, volume `S.volPct` (mirrors `S.volume`), climb tone from `vLift`, sink alarm `vSinkOn`/`vSink`, pitch `vF0` + `vFk` per m/s, beep speed `vRate`, tone `vWave` square/triangle/sine, near-lift ticks `vBuzz`, sound averaging `vDamp` s; test buttons (`beep.testRate`) play 3 s even with sound off.
- **Voice messages** (03 `say`, `VTXT` en/sv/fi, `vt()`; 08 `voiceEvent` from `fireEvent` + a 5 s timer): `S.voice`, `voiceLang` auto/en/sv/fi, `voiceVol` %, `voiceRate`; thermal start (`vcTherm`), thermal summary on leaving (`vcSum`: average, gain, time), turnpoint/goal (`vcTp`), airspace inside / within 2 km (`vcAir`, spoken when the warning changes), altitude every `vcAlt` min. Automatic action `say` speaks your own text on any event.
- **Tow launch** (02 `towDetect`, `towNow()`, `st.tows[]`, `st.towEnd`): straight climb ≥ `S.towMin` m/s (default 1) for 5 s without circling, within 90 s of takeoff or of the previous release (step towing); ends after 4 s below 0.3 m/s or circling (time/gain to the highest point). Events `towStart`/`towEnd` (automatic actions, voice summary `vcTow`); setting `S.towDetect` in Update & thermal mode. Widget `tow` (time, gain, average, blue while towing); visibility `vis: 'tow'` = while towing and `cfg.towKeep` s after release (default 60).
- **Tap and hold** (every widget): `cfg.tap` (`TAPG`, default `defTap`) and `cfg.hold` (`HOLDG`, default `defHold`: page buttons → page menu, alt/agl → heights, map/buttons → nothing, others → details). Holding never enters edit mode any more (edit via the menu, button action `edit`, or hold option `edit`). Hold after 400 ms (`runHold`): info options (details, heights, custom, time) show only while held and close on release anywhere (`endHold`, window-level pointerup, since the popup covers the widget); actions run once. Tap info opens `openInfo` (stays, live). **Custom info** (tap or hold `custom`): `cfg.infoItems` = any text widget types (rendered via `wData`) or 'heights', plus `cfg.infoText` note; edit-sheet rows appear only when tap or hold is `custom` (`INFO_KEYS`, `infoHTML`).
- **Height widgets** (`alt`, `agl`): default tap `heights` = popup with AMSL and AGL in ft and m; default hold shows the same while held. Tap/hold option `units` switches m ↔ ft in the widget (`switchUnits`).
- **Taps**: `st.tapGuard` is set when a widget tap opens something; `#dlg` ignores clicks within 500 ms of it (the click after the tap used to close the popup at once).
- **Edit bar** (`#wBanner`): moves to the other edge (class `bottom`) when the widget being dragged, resized or configured is under it and the other edge is free (`bannerAvoid`); ⇅ button `#wFlip` moves it by hand; the hint text hides below 1000 px width.
- **Airspace button** (`airbtn`, text widget, 3×2, title hidden, airplane icon `PLANE_PATH`): icon + count within `cfg.radius` km (default 20; `airStatus` covers 50 km); list options `cfg.rows` (default 25), `cfg.band` 'all' / 'height' (hides airspace entirely below you), `cfg.radio`; the popup (`openInfo(title, fn, W)`) has a Settings button → `enterEdit(W.id)` / icon only / icon + nearest (`cfg.look`); red when inside, orange within 2 km at your height. Default tap and hold `airlist` (TAPG/HOLDG 'Airspace & radio', `airListHTML(W)` in 08): nearby airspaces with limits, status and frequencies, then a Radio grid. Frequencies: parser reads `AF` + `AG` (station); files without them (XContest export) get them by airspace name from `data/airspace/freq.json` (written by the workflow from the OpenAIP files) in `loadXcsoarAir` (key suffix `|f1` forces one reload).
- **Wind arrow at you** (04 `windMark`, map options `windA` default on, `windAShape` arrow/chevron/tail, `windAS` size px (22), `windAD` distance px on the upwind side (46; under 24 px drawn above the glider), `windAC` colour (`WIND_COL`, blue), `windAO` opacity %, `windAT` label spd / spddir / none): a divIcon marker at the pilot, points where the wind blows to, turned by `w.to + map bearing` like the glider, so it reads right in any map orientation; hidden below 0.3 m/s or without wind.
- **Map pointer** (04 `ptrUpdate`, on map `move` and each `mapDraw`): while a map is moved away from you (`!I.follow`, not editing, `cfg.ptr` default on) a crosshair at the centre plus a card: distance and bearing from you (`COMPASS16`) and the shown airspaces at that point (lowest first, max 3, limits); "Back to me" hides it.
- **Map button outlines while editing** (`ctlGhosts` in 06, called from `renderWidgets`): the map widgets' own buttons (style, orientation, zoom, follow) stay laid out but invisible in edit mode and get dashed blue outlines in `.ctlGhost` above all widgets; red when a widget above the map covers one.
- **Small screens**: text widgets drop the sub line below ~70 px height and the title below ~48 px (titles stay in edit mode) so the value is visible; top-right corner `S.corner` 'auto' (menu only at ≤ 760 px wide or ≤ 480 px high) / 'full' / 'menu' (`cornerMode()`, body classes `cornerFull`/`cornerMenu`).
- **Conditional visibility** (`VIS`, `visDelay`) and "When tapped" options (`TAPG`, grouped) are in `COMMON` for every widget.
- **Airspace from XCSoar** (05 `loadXcsoarAir`, Settings → Airspace data): workflow `.github/workflows/airspace.yml` (+ `.github/scripts/airspace.py`) reads XCSoar's repository list (download.xcsoar.org/repository) and copies the newest national OpenAir file per country (OpenAIP exports: `fi_oaip`, `se`, `no`, `ee`) to `data/airspace/<key>.txt` + `index.json`; key `fi` = the owner's own XContest export (`fi_xcontest.txt`, OpenAir 1, `"manual": true` in index.json, kept by the workflow; replace the file and its date when the owner sends a new one); runs on pushes to dev, by hand, weekly (schedule only from the default branch). `S.airSrc` 'xcsoar' (default; reloads when `index.json` dates change, key `S.airUpd`, countries `S.airCountries`) or 'own' (OpenAIP key / file / Clear; older installs with airspace loaded stay 'own'). `parseOpenAir` reads OpenAir 2 `AY` (type; AC is then the ICAO class), drops FIR/UIR/NONE. Kinds (`airKind`: ctrl / restr / danger / tsa / rmz / other, from AY, OpenAIP type numbers, or for OpenAir 1 the name first (CTR/TMA/…, EFD…, EFR…) then AC, since XContest's class D holds both CTRs and danger areas) filtered by `S.airTypes` (default `AIR_KIND_DEF` = all kinds, owner's choice; Settings → Airspace data → Show); height filter `S.airMaxAlt` (m AMSL, default 3000, 0 = all; Settings → Airspace data): airspace whose floor is at or above it is hidden; `airShown()` (cached) feeds maps, warnings, voice, lists and the side view; NOTAM matching uses all.
- **NOTAM sources** (05 `NT_SRC`, `S.notamSrc`, default `NT_DEF` = all; Settings → Airspace data → Bulletins): ais.fi envfra, envfrm and efinen-fr (EFIN en-route, added 2026-10-16); a failing bulletin does not drop the others. `parseBulletin` handles the ais.fi VFR layout (text then "(A1234/26)", FROM:/TO:, LOWER:/UPPER:) and, when it sees "A1234/26 NOTAMN", the ICAO layout via `parseIcaoBulletin` (B/C times, D schedule, E text, F/G limits, Q-line centre + radius as fallback; NOTAMC skipped). The efinen-fr layout was not seen from the sandbox (ais.fi unreachable): check it on the tablet.
- Settings export/import covers layouts and configuration. Saved layouts from older versions must keep working (add migrations like `S.navBtnMig`, never break stored values).
- Map: Leaflet 1.9.4 + leaflet-rotate 0.2.8 (CDN). Tiles: OpenTopoMap, Esri imagery, Carto, OSM.
- External data: Open-Meteo, Overpass, OpenAIP (optional key or OpenAir file), ais.fi NOTAMs (may need a CORS proxy), FlyXC (route in the link `p=` param), Windy and Flyk embeds, **adsb.fi** open data for air traffic (personal non-commercial use; attribution is shown in the map credit and must stay).

## Testing (no framework yet)
Headless Chromium with Playwright works: `/opt/pw-browsers/chromium`, `playwright` installed globally in the cloud sandbox. The sandbox cannot reach CDNs, so route the Leaflet URLs to local copies (`npm pack leaflet@1.9.4 leaflet-rotate@0.2.8`) and stub or abort other external requests. Useful checks: open `index.html?demo`, no `pageerror`s; tap/hold buttons; open the edit sheet via `enterEdit(); openSheet(id)`; hit-test overlays with real pointer events. jsdom needs many stubs (canvas, layout, `L.Browser.any3d=true`), so prefer Chromium. Headless tests cannot judge how it looks or feels on the tablet; say so honestly.
Run `node --check js/*.js sw.js` after every edit. Responsiveness: measure taps with CPU throttling (`Emulation.setCPUThrottlingRate` 6, `deviceScaleFactor` 2) and the Event Timing API or a trace; headless draws canvases in software, so canvas timings overstate the tablet's GPU cost. To test the service worker, route with `context.route` (not `page.route`) and run with `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, otherwise the worker's own requests bypass the stubs; stubbed tiles need an `access-control-allow-origin: *` header.

## Product decisions and preferences (from the owner)
- Glove-friendly: large touch targets, no tiny controls. Landscape tablet is the main layout.
- Everything configurable, XCTrack-like: every page, every element a widget, duplicates allowed, small resize steps, blue drag handles on all corners.
- Numeric settings use − / number / + steppers (no preset pills). Option groups should be compact and grouped by function.
- Hamburger menu (top right) opens downward; page tabs auto-hide.
- Flights recorded here would be **unsigned IGC**: XContest accepts them but gives **no points**. The owner uses XCTrack on a separate phone for competition upload. There is no public XContest upload API.

## Known gaps / ideas
- IGC recording and saving from this app is not built yet (would need flight start/stop detection and periodic safety saves; downloading a file is fine).
- OGN (glider) traffic: no browser-friendly feed found; would need a small relay.
- Unverified: whether adsb.fi allows browser (CORS) requests from the hosted page; Flyk/FlyXC embedding permissions; ais.fi CORS; OpenAIP API details.
